# The Improve-this-page button opens the feedback dialog — evidence

> **Feature:** `PROFILE-006` · **Scenario:** `verify/scenarios/page-feedback.yml` · **Issue:** #58 · **Generated by:** `node verify/runner.mjs --only page-feedback --by agent` against a production build of the fix branch on 2026-11-16

A reader who spots a problem can now report it from any page. The floating "Improve this page" button (megaphone, in the theme's bottom-left button stack) and, on pages with an intro action bar, the green "Improve" button both open one "Share feedback" dialog that files a pre-filled issue in bamr87/bamr87.github.io labelled `page-feedback`. Before the fix, `_config.yml` had no `page_feedback:` block, so the theme rendered neither.

## How it was run

- **After** (every image without a `before-` prefix, and [`report.json`](report.json)): the branch was built with the production config (`JEKYLL_ENV=production bundle exec jekyll build` in `ruby:3.4`, `github-pages` gem, Jekyll 3.10, theme bamr87/zer0-mistakes@93e7062) and served locally. The scenario declines the cookie banner, checks the button and the inline trigger on `/profile/`, opens the dialog, then checks the button on the Quest Log post `/posts/2026/11/02/quest-log-bamr87/`. PASS at 390×844 and 1366×768: no console error, no horizontal scroll. The `profile_widget` eval in the report records the widget config (`repository: bamr87/bamr87.github.io`, `defaultLabels: [page-feedback]`, `mode: url`, AI off) and both no-JS links.
- **Before** (the `before-*.png` images): the live site, <https://bamr87.github.io>, which builds `main`, captured the same day at the same two viewports with the Playwright MCP after declining the cookie banner. Neither page has `#pageFeedbackFab` or any `[data-pf-open]` element.

The no-JS links read `issues/new?template=page_improvement.yml&labels=page-feedback`. The theme hard-codes that template name, and this repo's form is `page_feedback.yml`, so with JavaScript off GitHub opens a blank issue with the label rather than the form. The dialog path builds its own URL without a template and is unaffected. The template name is a theme fix in bamr87/zer0-mistakes.
