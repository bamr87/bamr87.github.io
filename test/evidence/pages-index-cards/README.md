# Every card on the paginated post index shows its image — evidence

> **Feature:** `PROFILE-007` · **Scenario:** `verify/scenarios/pages-index-cards.yml` · **Issue:** #23 · **Generated by:** `node verify/runner.mjs --only pages-index-cards --stamp --by agent` against a production build of the fix branch on 2026-11-16

A visitor paging through every post at `/pages/` … `/pages/6/` sees a picture on each card: the post's `preview`, or the site teaser when the post has none. Before the fix, two cards showed a broken image with the text "page preview image": the wizard post on `/pages/2/` (`src="/assets//assets/images/wizard-on-journey.png"`, a 404) and the doc-scraper post on `/pages/3/` (`preview: ""` became `src="/assets/"`, a folder, not an image). Five more cards loaded only because the web server collapses the `//` in `/assets//images/…`.

## How it was run

Both sites were built with the production config (`JEKYLL_ENV=production bundle exec jekyll build`: Ruby 3.4, `github-pages` 232, Jekyll 3.10.0) against the same theme commit, bamr87/zer0-mistakes@93e7062, and served locally with `python3 -m http.server`. The scenario scrolls each page to the card #23 reported, takes a screenshot at 390×844 and 1366×768, then follows the pagination links from `/pages/` and fetches every card image on every page.

- **Before** (`main` @ 6538202, the `before-*.png` images): FAIL at both viewports. "53 broken card image(s), 2 not loading: /pages/2/ "/assets//assets/images/wizard-on-journey.png" double slash, HTTP 404 … | /pages/3/ "/assets/" not an image (text/html …)". None of the 53 card images was lazy-loaded, and 6 had `//` in their path.
- **After** (the fix branch, every other image and [`report.json`](report.json)): PASS at both viewports. 6 pages, 53 cards, no broken image, no console error. The `card_images` eval in the report lists each card's page, `src`, `alt`, HTTP status and content type.

Locally `/assets/` answers with a directory listing (`text/html`); GitHub Pages answers 404. The scenario flags it either way, because a card image must come back as `image/*`.
